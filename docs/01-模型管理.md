# 模型管理层 — 学习笔记

## 为什么需要模型管理层

之前做 RAG 和 Agent 项目时，模型地址、API Key 都是硬编码在配置文件里的。换模型要改配置重启，模型挂了也没人知道。这次做中台，第一件事就是把模型抽象成**可管理的资源**。

## 模型注册中心

核心是 `ModelRegistry`，一个线程安全的注册表。用 `ConcurrentHashMap` 存模型元数据，`ReentrantReadWriteLock` 控制并发——读多写少的场景，读写锁比 `synchronized` 高效得多。

注册的模型分四类：`CHAT`、`EMBEDDING`、`RERANK`、`MULTIMODAL`。

## 健康探测

`ModelHealthChecker` 每 30 秒对所有已注册模型做一次健康检查。发现异常的自动标记不健康，路由时会跳过不健康实例。

## 智能路由策略

`ModelRouter` 实现了三种策略：

| 策略 | 选型逻辑 | 适用场景 |
|------|----------|----------|
| COST | 选最便宜的可用模型 | 对质量不敏感的批量处理 |
| PERFORMANCE | 选延迟最低的 | 实时对话场景 |
| QUALITY | 选上下文窗口最大的 | 复杂推理任务 |

## A/B 测试

`selectModelWithAB` 用租户 ID 的哈希值做灰度切流。同一个租户多次请求会稳定命中同一组。

## TPM 配额管控

`ModelQuota` 按模型维度统计每分钟 token 消耗量，超过 100000 TPM 的请求直接拒绝。
