# 多租户架构 — 学习笔记

## 行级隔离 vs 独立实例

**共享存储 + 行级隔离**（我选的方案）：所有租户数据在一个 Redis/一个表里，每条数据绑 `tenant_id`。成本低但代码里要处处带着租户过滤。

**独立实例隔离**：每个租户独立资源，强隔离。成本高，大客户专用。

## TenantContext 设计

`TenantContext` 用 `ThreadLocal` 存当前租户。网关层鉴权通过后塞入上下文。

异步场景下 ThreadLocal 会丢失，`TaskConsumer` 需要显式传入租户 ID。

## 模型白名单

`Tenant.modelWhitelist` 是最后一道防线——路由选出了模型后白名单校验。

## 配额与欠费熔断

`TenantQuotaManager` 按租户维度跟踪每日用量：10000 请求上限、1000000 token 上限。重置时间戳自动检测跨日。

## 关键踩坑

- ThreadLocal 用完 `remove()` 防泄漏
- WebFlux 下 ThreadLocal 不生效（本项目用 Servlet 模型）
- 白名单和路由交互：先路由再校验
